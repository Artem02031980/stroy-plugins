# AGENTS.md — сайт инженерных инструментов (проект `stroy-plugins`)

Проектные правила для агента. Файл грузится в baseline каждой сессии в этом репозитории,
поэтому держать его компактным. Общие правила машины — `~/.dsh/AGENTS.md`.

## 1. Что за проект

Сайт для инженеров-проектировщиков и инженеров-конструкторов. Три направления:

1. **Бесплатные онлайн-инструменты** — инженерные калькуляторы без регистрации, основной
   источник органического поискового трафика.
2. **Инженерные программы** — каталог и продажа собственных программ, у каждой своя страница.
3. **Полезные материалы** — статьи и инструкции по расчётам, ссылающиеся на инструменты и программы.

Экономика проекта: поисковый трафик → бесплатный инструмент → переход к коммерческой программе.
Первая версия (MVP) намеренно простая; архитектура обязана позволять добавлять калькуляторы,
программы, статьи и пользовательские функции без переделки существующего.

## 2. Жёсткие требования (из ТЗ, на этапах реализации не обсуждаются)

- **SEO** — отдельный URL и отдельная индексируемая страница на каждый инструмент; серверная
  отдача содержимого (без выполнения JS); уникальные title и description; корректные H1–H3;
  canonical; sitemap.xml; robots.txt; Open Graph; человекочитаемые URL; корректные HTTP-коды;
  скорость; адаптивность.
- **Расчёты — на Python**, отделены от HTML: вход JSON → выход JSON, валидация входных данных,
  понятные ошибки. Часть существующих расчётных модулей заказчика позже переносится на сайт.
- **Калькуляторы независимы**: метаданные (название, slug, категория, SEO, информационная часть)
  плюс расчётный модуль. Каталог и главная формируются из реестра; добавление инструмента
  не требует правок в них.
- **Контент правится без кода**: статьи, программы, версии, цены, изображения, SEO — через админку.
  Расчётные модули добавляет разработчик кодом.
- **Развёртывание** — Docker/Docker Compose на своём VPS; без критичной зависимости от платных платформ.
- **Безопасность** — HTTPS; валидация пользовательских данных; лимиты размера и проверка типов
  файлов; загруженное содержимое не исполняется на сервере; секреты вне репозитория; защита API
  от очевидного злоупотребления.
- **Передача** — весь код, схема БД, Docker-конфигурация, инструкции по развёртыванию и бэкапу.
  Проект не зависит от аккаунтов разработчика: домен, сервер, аналитика, репозиторий — на владельца.

## 3. Протокол работы с заказчиком (главное)

1. Заказчик присылает задание вида «Выполни этап N» и при необходимости — обновлённый текст этапа
   из своей памятки `Этапы проекта.docx`.
2. Обновлённого текста нет → беру формулировку из § 5 и не додумываю объём работ.
3. Обновлённый текст есть → он приоритетнее § 5: выполняю по нему, затем переписываю этап в § 5
   и дописываю строку в § 7 «Журнал изменений».
4. Нумерация этапов стабильна: новые этапы идут в конец (34, 35, …), существующие номера не
   сдвигаются, чтобы ссылки «этап N» не ломались. Этап можно дробить — номер сохраняется,
   шаги становятся отдельными пунктами.
5. Работаю строго в границах названного этапа. Всё, что выходит за них, — только предложением
   в отчёте, без самовольной реализации.
6. Отчёт после работы: 3–5 строк с числами, список изменённых файлов, что и как проверено.
7. Статус этапа в § 5 меняю сразу после выполнения: `не начат` → `в работе` → `готов`.
8. Памятку `Этапы проекта.docx` агент не редактирует — это документ заказчика. Обновления этапов
   по умолчанию идут только в этот файл.

- Коммиты: по-русски, схема «Область: что сделано» (как в соседних проектах заказчика).
  Один этап — один коммит или несколько по шагам; пуш в `origin main` после завершения этапа.
- Кодировка файлов UTF-8; перевод строк нормализует git (`core.autocrlf=true`).
- Временные скрипты и замеры — в корне проекта с префиксом `.tmp-` (в `.gitignore`), удалять
  после задачи; многоразовые инструменты — в `~/.dsh/bin/`, а не в репозитории.
  Удалять их поимённо, а не маской `Remove-Item .tmp-*`: в проекте могут работать параллельные
  агенты, и маска сносит чужие файлы (случай 08.10.2026).
- Вёрстку проверять только по `http://`, не по `file://` (модули не грузятся из-за CORS).
- Параллельным агентам выдавать разные наборы файлов и запрещать `git`-команды: репозиторий
  ведёт только основной агент.
